# 方圆里 v0.73 交互迁移契约

更新时间：2026-08-02

## 1. 目的

本文件把已经在 v0.73 原型中反复验收的交互经验迁移到正式 Flutter App，同时保留当前 Flutter 版本更清爽的图标、配色和页面质感。

迁移不是复刻旧原型，而是分离三层职责：

| 层级 | 权威来源 | 处理原则 |
|---|---|---|
| 视觉 | 当前 Flutter App | 保留当前图标、色彩、圆角、排版和整体质感 |
| 交互 | v0.73 原型与本契约 | 迁移入口、操作反馈、页面跳转、返回路径和状态连续性 |
| 业务与安全 | `PRODUCT_SPEC.md`、API、数据模型和服务端 | 服务端判权和持久化，不能用原型模拟状态代替 |

发生冲突时，按“用户最新明确决定 → `PRODUCT_SPEC.md` → 本契约 → v0.73 原型”的顺序处理，并在编码前报告冲突。

## 2. 实现边界

- v0.73 的按钮、页面、弹层、状态和返回路径应按 `V073_INTERACTION_LEDGER.md` 系统迁移；用户举出的单个控件只是交互样例，不代表迁移范围仅限该控件。
- 不复制 v0.73 的 HTML、CSS 或 JavaScript。
- 不因为先铺 UI 而把模拟数据写进正式 Repository 或数据库模型。
- 展示层只依赖 ViewModel 和明确的操作回调，不直接拼接 API 字段。
- 公共行为只实现一次；广场、地点、活动和好友聊天不得各复制一套输入框。
- 每个可点击控件必须产生明确结果：完成操作、打开页面、打开弹层或显示“开发中”反馈，禁止无响应按钮。
- UI 外壳可以先于真实后台出现，但必须用开发状态标识与真实功能区分。

## 3. 通用导航契约

每条交互路径至少记录以下信息：

1. `source`：从哪个 Tab、列表、详情页或系统通知进入；
2. `destination`：打开页面、底部弹层、对话框、键盘还是系统能力；
3. `returnTarget`：返回到原入口，而不是按目标业务强制跳到底部首页；
4. `preservedState`：保留滚动位置、筛选条件、草稿、选中项和已读进度；
5. `sideEffects`：未读数、列表排序、关系状态或权限是否改变；
6. `role`：本人、好友、陌生人、群主、管理员和普通成员的差异；
7. `failure`：加载中、空页面、断网、权限拒绝和服务端失败时的反馈。

Flutter 实现优先使用真实导航栈返回。需要跨模块打开同一页面时，显式传入来源上下文，禁止通过全局变量猜测返回目标，也禁止无条件 `popUntil` 到首页。

## 4. 全局入口

| 操作 | 目标 | 返回与状态 |
|---|---|---|
| 顶部搜索 | 全局分类搜索 | 返回原 Tab；保留原列表位置和筛选 |
| 顶部 `+` | 发布动态、创建活动、扫码 | 取消回原页面；有内容时按产品规则询问草稿 |
| 点击任意用户头像 | 对应用户资料 | 返回头像所在的聊天、评论、申请或通知页面 |
| 点击系统通知 | 对应申请、活动或动态详情 | 返回原系统通知列表 |
| 点击动态 | 同一份动态详情 | 从广场、好友动态、资料或通知进入时分别返回原来源 |

## 5. 统一聊天契约

### 5.1 消息布局

- 对方消息：头像在左、消息气泡在右；群聊可显示发送者名称。
- 本人消息：头像在右、消息气泡在左；不额外显示“我”字。
- 点击对方头像进入对方资料；点击本人头像进入本人资料；返回后仍停留在原聊天进度。
- 头像、气泡、发送状态和时间属于同一个公共消息组件。
- 资料头像更新后，新渲染的消息必须使用同一份资料媒体数据，不在消息记录中复制永久头像 URL。

### 5.2 输入状态

统一输入组件状态为：

| 状态 | 主区域 | 辅助面板 |
|---|---|---|
| 文字 | 多行文本框 | 无 |
| 语音 | “按住 说话” | 无 |
| 表情 | 文本框 | 基础表情或我的表情 |
| 更多 | 文本框 | 照片、拍摄、位置等能力 |

状态切换规则：

- 语音按钮在文字与语音模式之间切换；回到文字模式时恢复原草稿。
- 表情面板和更多面板互斥；点击输入框切回系统键盘。
- 点击聊天空白区域收起键盘或面板，不改变草稿。
- 发送基础表情或自定义表情后面板保持打开，支持连续发送。
- 文本非空时显示发送动作；空文本时显示更多动作。
- 每个会话独立保存未发送草稿。

### 5.3 更多能力

- 照片：调用系统相册，支持后续多选、顺序和重复选择限制。
- 拍摄：调用系统相机，并遵循一次授权后不重复询问的系统权限机制。
- 位置：先打开“发送位置 / 共享实时位置”选择层，再进入对应地图流程。
- 媒体能力复用统一上传、压缩、断网续传和账号隔离基础设施。

### 5.4 消息操作与滚动

- 长按文字：引用、转发、多选、删除。
- 长按表情：在文字操作基础上增加“添加表情”。
- 群聊长按头像：在当前输入框插入 `@用户`。
- 发送文字、语音、图片或表情后，消息必须完整出现在可视区域底部。
- 进入聊天默认显示底部最新进度；存在未读时显示“N条新消息”，点击定位首条未读。
- 返回会话列表后，已读状态和底部导航未读数以服务端游标为准。

## 6. 五栏关键路径

### 6.1 广场

- 主广场和三个相邻广场在同一页面切换，保留各自滚动与草稿状态。
- 四个广场均可发言，资格由位置与锚点规则在服务端判定。
- “聊天 / 动态”切换保留各自滚动位置、筛选和未读状态。
- 相邻广场、动态详情和用户资料返回时回到原广场上下文。

### 6.2 地点

- 点击地点卡片主体直接进入地点聊天；聊天右上角进入地点详情。
- 搜索、类型、距离、活跃度和历史进入属于列表状态，进入详情后返回不得重置。
- 从“历史进入”打开地点聊天，返回必须回“历史进入”，不能跳到地点首页。
- 群主和管理员的管理入口由服务端角色决定，普通用户不显示管理按钮。

### 6.3 活动

- 点击活动卡片的“活动详情”进入详情；点击卡片其他位置进入聊天。
- 从“我的活动”进入详情或聊天，返回必须回“我的活动”。
- 申请加入、审批、成员、公告和群聊设置各自使用独立页面或弹层，并按原路径返回。
- 已结束活动进入“已结束”，记录仍按保留规则可查看和聊天。

### 6.4 好友

- “消息 / 联系人”保留各自滚动位置。
- 好友申请作为系统消息进入；处理后保留“已同意 / 已拒绝”状态，未处理项排在前面。
- 从好友申请进入资料，返回必须回好友申请。
- 私聊设置、好友资料和资料中的关系设置操作同一份服务端关系数据。

### 6.5 我的

- 资料 → 编辑资料保存后回资料；取消不改变资料。
- 好友动态、我的活动、历史进入、账号与安全均为独立导航来源。
- 从历史进入打开广场、地点或活动聊天，返回必须回历史进入。
- 黑名单解除后根据服务端保存的原关系恢复好友或陌生人状态。

## 7. 验收与自动化

每批迁移至少覆盖：

- 入口 → 目标 → 返回的 Widget 测试；
- 返回后的列表滚动、筛选、草稿或已读状态；
- A/B 双账号看到的头像、消息、关系和权限差异；
- loading、empty、error 和权限拒绝状态；
- 公共组件在广场、地点、活动和私聊中的一致行为；
- 真实功能与预览功能具有可辨认状态，不出现僵尸按钮。

## 8. 分批实施

实施状态统一记录在 `V073_INTERACTION_LEDGER.md`，不能依赖聊天记录或个人记忆判断遗漏项。

1. 统一聊天消息和输入组件；
2. 建立来源上下文与返回路径测试；
3. 用当前视觉补齐五栏 UI 外壳；
4. 迁移动态、地点和活动的卡片、详情与筛选交互；
5. 按真实业务纵切逐项接入后台；
6. 每完成一个模块进行人工验收并冻结该批交互。

# 方圆里 v0.73 交互迁移总账

更新时间：2026-08-02

## 1. 总账用途

v0.73 不是供开发人员挑选样式的旧页面，而是已经经过多轮人工验收的交互基线。用户后续提到的头像、`···`、输入框、返回路径等内容都只是例子，不能只修复被举例的控件。

正式 Flutter App 的迁移目标是：

- 保留当前 Flutter App 的视觉语言；
- 系统迁移 v0.73 的入口、状态变化、弹层、导航与返回逻辑；
- 使用正式 API、权限模型与持久化实现业务，不能照搬原型的内存模拟；
- 每完成一批，按本总账验收并更新状态，避免靠人工记忆发现遗漏。

状态说明：

- `已接入`：正式 Flutter 页面与真实业务链路已经存在；
- `部分接入`：已有页面或后台，但交互尚未达到 v0.73 基线；
- `待迁移`：仅在 v0.73 中完整存在；
- `需后台`：UI 可以先完成，但最终需要 API、实时事件或系统能力支持。

## 10. 实施顺序与冻结规则

1. 先完成公共导航来源、统一聊天组件、未读与操作反馈基础设施；
2. 用当前 Flutter 视觉补齐五栏页面外壳，但每个未接后台的入口必须显示明确状态；
3. 按“好友 → 广场 → 地点 → 活动 → 动态/全局搜索 → 我的与系统能力”逐条完成业务纵切；
4. 每条纵切同时覆盖 API、数据模型、服务端权限、Flutter 状态、失败反馈和测试；
5. 每批通过自动化与人工验收后标记冻结；以后改动必须更新对应测试和本总账；
6. 不因用户举出一个例子就只修一个控件；先检查同类入口是否需要统一调整。

## 11. 每批完成定义

一项只有同时满足以下条件才可从“部分接入/待迁移”改为“已接入”：

- 入口、目标页面、操作结果和返回路径完整；
- 本人、好友、陌生人、群主、管理员、成员等角色判定由服务端负责；
- 刷新、重启、A/B 账号与多设备状态一致；
- 加载、空页面、网络失败、权限拒绝均有反馈；
- 关键路径有自动化测试；
- 当前 Flutter 视觉保持一致；
- 不存在无响应按钮、只改本地假状态或跨模块复制业务逻辑。

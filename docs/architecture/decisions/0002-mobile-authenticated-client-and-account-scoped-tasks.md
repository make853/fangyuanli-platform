# ADR 0002：移动端共享鉴权客户端与账号归属任务

- 状态：已接受
- 日期：2026-08-01
- 范围：Flutter 客户端网络层与可恢复后台任务

## 背景

好友、会话、资料、实时补偿和媒体模块最初分别创建 `AuthenticatedApiClient`。继续增加地点、活动、动态和通知后，这会重复连接配置、令牌刷新与错误处理，也难以统一处理退出登录和账号切换。

媒体上传任务会跨进程持久化。如果任务只记录本地文件和上传凭证，不记录创建它的账号，A 退出后 B 登录可能错误恢复 A 的任务，甚至使用 B 的令牌确认 A 的媒体。

## 决定

1. App 根组合层向核心网络层注入唯一的会话加载函数；
2. 鉴权客户端由共享 Provider 创建和释放，业务 Repository 只依赖该客户端，不直接依赖登录控制器；
3. 未配置会话加载器时，客户端可以安全构造，但真正发起鉴权请求会返回未登录错误，便于页面和模块独立测试；
4. 对账号敏感的延迟请求可以传入 `expectedUserId`，当前会话账号不一致时在发出 HTTP 请求前终止；
5. 每个持久化媒体任务必须保存不可变的 `ownerUserId`；读取、替换、删除和恢复均以账号为边界；
6. App 登录成功或重启恢复会话后，只自动恢复当前账号的可恢复任务；退出或切换账号会重建恢复作用域；
7. 媒体任务存储升级为 `upload_tasks.v2.json`。旧版任务没有可靠账号归属，不自动迁移或猜测续传；
8. COS 原始文件上传可能在退出瞬间完成，但后续业务确认仍必须通过账号一致性和服务端归属校验。
9. App 冷启动只从安全存储恢复尚未过期的刷新凭证，不等待网络刷新访问令牌；页面先使用账号隔离的本地快照展示。访问令牌按需续期时，连接失败、超时、限流或服务端暂时故障不得清除本地登录，只有刷新凭证被明确拒绝或已过期才退出账号。

## 结果

正面影响：

- 令牌刷新、超时、请求头和后续日志/追踪只有一个扩展入口；
- 新增登录方式时主要修改认证组合层，不需要逐个业务模块重写；
- A/B 账号切换不会交叉恢复媒体任务，也不会用错误账号完成确认；
- 可恢复任务形成通用先例，未来草稿、离线消息和后台处理都必须显式记录账号归属。
- 访问令牌短期过期或 staging 隧道暂时中断时，App 仍能立即进入并展示本地数据；恢复联网后共享鉴权客户端自动重试续期。

需要承担：

- 旧版未归属上传任务会留在旧文件中，不会自动恢复；
- 当前批次不主动取消已经发往 COS 的原始 PUT，请求结束后由未确认对象的清理策略兜底；
- 自动恢复目前依赖 App 存活，真正的 iOS 后台上传需要未来单独设计系统后台任务；
- 账号归属是客户端防误用措施，不能替代服务端鉴权和资源所有权校验。

## 不采用的方案

- 各模块继续创建独立客户端：配置与刷新逻辑会持续复制；
- 根据当前登录账号认领旧任务：可能把 A 的本地数据错误归给 B；
- 只在界面隐藏其他账号任务：后台仍可能错误提交；
- 当前就引入复杂后台上传调度器：尚未完成真实 COS 端到端验证，范围过大。

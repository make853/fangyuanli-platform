# 0010：移动端定位与广场缓存边界

- 状态：已接受，等待真实高德地图对照验收
- 日期：2026-08-02

## 背景

Flutter 稳定生态可以读取 iPhone 的 CoreLocation 原始位置，但高德官方
Flutter 定位插件长期未维护，当前版本仍限制旧 Dart SDK。直接引入会把构建、
权限和坐标逻辑绑定到停更依赖。与此同时，广场接口只接受 GCJ-02，不能把
WGS-84 改个字段名后提交，否则四广场、距离和150米锚点都会整体偏移。

广场页面还必须符合本地优先体验：打开页面先显示最近一次成功取得的四广场，
再静默确认当前位置；但缓存不能让已经过期的位置资格继续用于发言。

## 决策

1. iOS 第一版使用系统定位作为原始传感器，只在进入附近能力和用户主动刷新时
   获取一次高精度位置，不启动后台持续定位。
2. WGS-84 到 GCJ-02 的转换放在独立 `Gcj02CoordinateConverter` 端口，页面、
   Controller、API Repository 和会话模块都不能自行转换或重命名坐标系。
3. 地图展示、POI、逆地理编码和导航仍统一使用高德；以后接入高德原生定位 SDK
   时，只替换 `DeviceLocationSource`，不修改广场业务和接口模型。
4. 正式发布前，必须使用真实 iPhone 将转换结果与高德 SDK/高德地图对照验证；
   若误差不满足要求，替换适配器而不是在页面叠加修正值。
5. 本地只按账号缓存四广场摘要和锚点半径，不缓存精准经纬度，也不持久化短期
   `locationContextToken`。缓存只负责平稳首屏，不能代表当前仍有查看或发言资格。
6. 每次成功刷新后，内存保存新令牌和到期时间；定位失败时保留缓存页面并给出
   重试入口，不清空旧页面、不白屏，也不把缓存资格当成新资格。

## 影响与风险

- 中国大陆边界附近和不同 iOS 版本可能存在坐标差异，必须纳入真机验收样本。
- 单次高精度定位通常比持续监听省电，但定位被永久拒绝时需要引导用户进入系统
  设置；第一版先提供明确反馈，后续再补系统设置直达入口。
- 广场未读来自服务端摘要；缓存中的红灰点可用于平稳展示，但底部红点只统计
  红色未读，灰色免打扰消息不能进入导航总数。
- 后续地点、活动和附近动态必须复用同一位置上下文与定位端口，禁止各自再次申请
  定位或建立平行坐标缓存。

## 验收标准

- 真机首次授权后能取得真实四广场，响应和本地日志不展示精准位置。
- 冷启动先显示账户缓存，后台刷新不让整个页面闪白或重建导航栈。
- 飞行模式下可看到缓存广场，但发言资格标记为未确认。
- 位置令牌到期、定位精度大于80米、权限拒绝和服务不可用都有可恢复反馈。
- 北京、广州样本转换有自动测试，最终以真实 iPhone 对照高德结果作为放行依据。

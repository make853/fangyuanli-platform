# ADR 0013：首版广场采用两公里版本化网格

- 状态：已接受
- 日期：2026-08-02
- 替代：ADR 0011 的一公里首版基线

## 背景

一公里网格已经通过真实 iPhone 定位、固定展示名和四广场同屏验证。实际位置靠近四格交界时，四个网格中心均可能在约 700 米附近；这符合几何规则，但主广场加三个相邻广场只覆盖约 4 平方公里，冷启动阶段容易把县城、郊区和低密度区域的用户过早分散。

方圆里首版更需要先形成可感知的附近交流密度。当前尚无正式运营用户和生产消息，适合在上线前完成最后一次统一基线调整。

## 决策

1. 首版激活边长为 2000 米的正方形网格版本。主广场加三个相邻广场组成约 4 公里乘 4 公里的四格区域，总面积约 16 平方公里。
2. 不修改已经进入共享环境的一公里版本。数据库通过前向迁移将版本 2 退役并激活版本 3；用户下一次刷新地理上下文时自动建立版本 3 锚点。
3. 旧广场、会话和测试消息不删除。网格版本是广场身份的一部分，退役版本不再由新的地理上下文返回，但保留审计与回退能力。
4. 150 米锚点不随边长变化；版本切换会立即接受新版本组合，不继承旧版本锚点。原连续定位确认和停留时间策略后来由 ADR 0021 取代。
5. 网格边长继续只存在于服务端版本数据，移动端不得依据距离猜测版本或写死两公里。
6. 后续密度适配必须基于真实匿名聚合数据设计。高密度城区、低密度区域和大型场馆可以采用不同覆盖策略，但不得直接修改已经激活并承载消息的版本。

## 影响

- 同一位置的四广场中心可能仍都距用户较近；中心距离不是网格边长。相邻网格中心在投影平面上相距约 2 公里。
- 四格最外侧对角线约 5.66 公里，提升低密度区域的交流机会，同时仍保持本地附近语义。
- staging 刷新定位后会生成新的四个广场和名称，旧的一公里测试卡片不再出现；这不是改名，而是网格版本切换。
- 正式运营前必须完成真机定位、四格命名、锚点稳定和 A/B 同群验收。正式运营后不得无迁移方案再次统一换网格。

## 验收

1. 数据库只有版本 3 为 `active`，其边长为 2000 米；版本 1、2 保持 `retired` 且原记录不被改写；
2. 用户刷新 `/geo/context` 后得到四个版本 3 广场，旧锚点自动替换；
3. 同一坐标的不同账号得到相同主广场 ID、名称和会话 ID；
4. 四个广场均可查看和发言，原有 150 米锚点稳定机制继续生效；
5. 返回结果不包含网格坐标、网格中心或用户精确位置。

# ADR 0003：COS 使用 CVM 实例角色临时凭证

- 状态：已接受
- 日期：2026-08-01
- 范围：staging 与 production 媒体对象存储鉴权

## 背景

媒体模块需要为 App 签发短期 COS 直传 URL，并在上传完成后读取和删除对象。把长期 SecretId、SecretKey 写入服务器 `.env` 虽然部署简单，但一旦环境文件、日志或备份泄露，密钥会持续有效，轮换也会影响运行服务。

## 决定

1. staging 和 production 的 CVM 绑定专用 CAM 角色；
2. API 通过腾讯云实例元数据取得自动轮换的临时凭证，不持久化长期 SecretKey；
3. 角色只允许目标私有桶 `temporary/*` 前缀的 `PutObject`、`HeadObject` 和 `DeleteObject`；
4. COS 桶保持私有，客户端只得到短期、单对象、单方法的预签名 URL；
5. 服务端存储适配器对凭证来源保持无感，实例角色与本地开发静态密钥共用同一业务接口；
6. 本地静态密钥入口保留用于必要的独立开发，但不能作为正式部署方案；
7. 原生 iOS/Android 直传不配置浏览器 CORS；未来启用 Web 客户端时，只允许确定域名和必要方法；
8. 部署后用一次性诊断对象验证预签名 PUT、HEAD 和 DELETE，测试对象必须清理。

## 结果

正面影响：

- 服务器无需保存长期云密钥；
- 凭证自动轮换，角色可集中撤销；
- 权限被限制在指定桶和临时前缀；
- 更换凭证策略不会进入媒体业务层或 Flutter 客户端。

需要承担：

- API 依赖 CVM 实例元数据可用；
- 角色、策略和实例绑定需要独立部署步骤；
- 真实 COS 集成必须在腾讯云环境验证，纯本地测试只能验证签名和适配器行为；
- 未来正式媒体归档、缩略图和清理 Worker 需要新增独立前缀权限，不能扩大现有临时前缀策略来偷懒。

## 不采用的方案

- 在正式服务器保存主账号长期密钥：泄露面和权限范围过大；
- 把桶改为公有读写：无法满足用户媒体、投诉证据和认证资料的隐私要求；
- 给角色授予整个 COS 服务的全权限：不符合最小权限原则；
- 由 App 持有腾讯云永久密钥：客户端密钥可以被提取，属于不可接受的越权风险。

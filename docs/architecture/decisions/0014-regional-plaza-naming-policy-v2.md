# ADR 0014：区域级广场命名策略 v2

- 状态：已接受
- 日期：2026-08-03
- 补充：ADR 0012 的候选发现、排序和自动改名规则

## 背景

两公里网格真机验收中，首批稳定名称出现“庄周双语小学、民权县欢欢幼儿园、中医院门诊综合楼、雅芝林商学院”等结果。这些地点可能离网格中心最近，但不能代表居民长期认知中的区域，也暴露出三类系统性问题：

1. 只依赖逆地理编码的近邻 POI，区域级地标不一定进入候选；
2. 把“科教文化、医疗”等大类整体视为稳定，幼儿园、培训机构和医院内部楼宇会被高估；
3. 已经自动命名的广场无法在算法改进后安全重算，只能手工改库。

广场名称会被固定居民长期、反复看到，因此需要稳定、熟悉、可区分，也必须允许策略在不改变广场身份的前提下演进。

## 决策

1. 候选发现采用两路并行：逆地理编码在网格中心 1600 米内发现 AOI、商圈和本地兜底；周边搜索在 3000 米内发现城市广场、公园、公共场馆、交通枢纽、大型商场、医院和大学等区域级地标。任一路失败仍可使用另一路，全部失败才进入重试。
2. 排序先看实体语义，再看距离：城市广场、公共文化体育场馆和交通枢纽优先；大型商场、主体医院和大学次之；商圈、大型 AOI 和社区用于降级；普通中小学只作为最后兜底。
3. 幼儿园、托育、培训机构、办公室、管理所、公交站、小商铺、停车场、入口和内部附属设施不得成为区域名。医院门诊楼、住院楼等先归并到医院主体；地铁出入口归并到站点主体。
4. 类型优先于名称中的巧合词。例如“广场花苑”仍是住宅社区，银行或门店名称中包含“城市广场”也不能冒充公共广场。
5. `plaza_grids.naming_policy_version` 记录自动展示名采用的策略版本。策略升级时只原子认领中性名称或旧策略名称，更新 `display_name`、`naming_source` 和策略版本；`plaza_grids.id`、网格、`conversation_id`、消息和未读状态保持不变。
6. 自动重算仍使用数据库租约和失败退避。同一批四广场避开重复名称；地图无合格候选或服务异常时保留旧名称，不让定位和进群主流程等待或失败。
7. 运营人工名、认证大型场馆名等未来来源必须拥有高于自动地图名的独立来源与审计规则，不能借策略版本静默覆盖。

## 影响与风险

- 每个首次命名或策略升级的网格最多并行产生两次高德 Web 服务请求；数据库租约确保用户刷新不会重复放大请求。
- 3000 米搜索是候选发现范围，不等于广场聊天覆盖范围；最终名称仍由语义、距离和同批去重共同决定。
- 高德数据分类可能仍有错误，因此排序规则保持为独立领域组件并通过真实错误样本回归测试，后续无需改动广场核心模型。
- 命名版本解决自动策略演进，但不替代运营改名审核、重名消歧和名称变更历史；这些在正式开放人工命名前单独设计。

## 验收

1. 当前真实错误样本中的幼儿园、办公室、培训机构不会进入候选；
2. 医院内部楼宇合并为医院主体，地铁出入口合并为地铁站主体；
3. 周边区域级广场、公园或交通枢纽能排在普通学校和社区之前；
4. 逆地理编码或周边搜索任一路失败时仍能得到另一来源的候选；
5. 旧策略名称可自动升级且广场 ID、会话 ID、消息和未读均不变；
6. 完整自动测试、迁移测试和 staging 真机四广场刷新通过。

# 0008：统一会话缓存与同步引擎

- 状态：已接受
- 日期：2026-08-02

## 背景

好友私聊已经通过真机冷启动、飞行模式读取和恢复联网验收，但方圆里的聊天并不只有私聊。广场、地点、活动和系统通知也都具有消息历史、未读游标、实时增量、媒体过期、回复引用和搜索定位。如果按页面分别实现缓存，会出现五套消息表、五套合并规则和五种冷启动体验，任何修复都要重复修改并容易产生差异。

服务端数据模型已经把 `plaza`、`place`、`activity`、`direct` 和 `system` 统一为 `conversation`，共用消息、会话序号、已读游标、通知设置和实时事件。移动端必须保持相同边界。

## 决策

1. 移动端只保留一套账号隔离的会话消息存储和同步引擎。所有消息以 `(owner_user_id, conversation_id, message_id)` 幂等存储，并以 `(owner_user_id, conversation_id, sequence)` 保证会话内顺序。
2. 私聊、广场、地点、活动和系统会话共用消息分页、`beforeSequence`、`afterSequence`、`anchorSequence`、实时合并、已读推进、缓存损坏回退和冷启动逻辑，禁止模块另建消息数据库或复制控制器。
3. 通用消息模型必须支持 `text`、`image`、`voice`、`video`、`sticker`、`location`、`liveLocation`、`activityCard` 和 `systemEvent`，并保留回复、提及、发送状态、删除状态、过期时间及稳定媒体 ID。首条私聊纵切已经无损升级为 `ConversationMessage`，后续场景不得再定义平行消息模型。
4. 通用引擎只处理数据一致性，不自行判断业务权限。每种会话通过策略端口提供详情、能力和发送上下文：
   - 私聊校验好友与拉黑关系；
   - 广场发送携带短期位置上下文并校验当前四广场资格；
   - 地点校验可见、认证角色、禁言和群规则；
   - 活动校验群主、管理员、已报名、附近用户、活动状态和发言规则；
   - 系统会话默认只读，只接受平台生成卡片。
5. “能否发送”和“能否读取历史”分开建模。用户失去当前位置或发言资格后，不因此立即删除已经合法缓存的历史；服务端在同步和详情接口中返回最终读取能力，客户端不得用缓存绕过封禁、删除或隐私裁剪。
6. 媒体二进制继续由媒体缓存管理，消息库保存稳定媒体 ID、展示元数据和过期状态。签名地址刷新不得清空消息；媒体到期显示占位，不破坏消息序号和回复关系。
7. 离线发送队列必须复用统一 outbox，以稳定 `clientMessageId`、账号、会话、消息类型和发送状态实现幂等；不得为私聊和群聊分别实现重试队列。
8. 本地清理依据会话类型、服务端保留策略和用户操作执行。文字索引、媒体文件、资料缓存和账号退出清理是独立动作，不能用一个“清缓存”按钮全部删除。
9. Flutter 通用消息、存储和同步引擎使用 `Conversation` 命名；`DirectChatScreen` 仅保留为私聊场景适配器。数据库升级必须非破坏性迁移现有真机私聊缓存，不能要求用户清数据。

## 实施记录

- 2026-08-02：移动端数据库升级至 v4，将 `direct_message_threads` 和 `direct_messages` 原位改名为统一会话表；迁移测试证明已有私聊缓存和分页状态不丢失。
- 2026-08-02：`ConversationMessage` 已覆盖契约中的九类消息及发送者、媒体、回复、提及、载荷和过期字段；旧私聊文字接口继续使用同一模型。
- 2026-08-02：本地优先加载、序号增量、实时去重、已读推进和持久化已抽取为 `ConversationSyncController`，私聊成为首个场景适配器。
- 2026-08-03：广场成为第二个真实场景适配器。服务端新增统一 `ConversationAccessService`，将“读取历史”与“当前位置发言”分离；短期位置令牌绑定当次四广场 ID，不能跨区域重放。移动端只注入广场访问上下文，继续复用同一 `ConversationSyncController` 和 SQLite 消息表。
- 2026-08-03：广场消息使用一年文字保留期；首次合法进入会写入通用历史记录，离开当前四广场后仍可读取历史但不可远程发言。广场未读、首条未读、全局群免打扰与单群通知覆盖均复用统一游标和实时事件，并以 `navigationKey=plaza` 与好友未读隔离。
- 2026-08-03：数据库升级至 v5，统一持久化 outbox 正式落地。文字消息先本地乐观显示，失败保留红色重试入口，确认消息按稳定 `clientMessageId` 替换；实现细节见 0017。
- 地点和活动在获得真实 `conversationId` 与对应资格策略前不得把预览数据写入统一缓存。

## 场景适配边界

| 能力 | 通用引擎 | 场景策略 |
|---|---|---|
| 本地消息、排序、去重、分页 | 是 | 否 |
| 实时合并和断线补偿 | 是 | 否 |
| 未读游标与搜索锚点 | 是 | 导航归属由场景提供 |
| 消息气泡、时间、回复、媒体占位 | 是 | 角色标签可扩展 |
| 是否可进入、查看和发言 | 否 | 是 |
| 位置令牌、群角色、禁言、活动状态 | 否 | 是 |
| 详情页和管理入口 | 否 | 是 |

## 影响与风险

- 私聊中已经解决的无闪屏、本地先显示和后台增量更新会自然覆盖全部聊天窗口。
- 群聊接入成本集中在场景权限与详情，不重复开发消息底座。
- 通用模型字段会比当前文字私聊多，但通过可选载荷和独立渲染器扩展，不让场景字段污染消息同步引擎。
- 广场切换、地点隐藏和活动结束不会自动等于删除缓存；读取资格与本地保留必须分别测试，避免隐私泄露。
- 统一引擎是模块化单体内的共享能力，不意味着把地点、活动和地理领域合并到会话模块。

## 验收矩阵

每种真实聊天上线前至少验证：

1. 首次联网加载、退出页面返回、彻底退出 App 冷启动；
2. 飞行模式读取、恢复网络增量补拉、重复实时事件去重；
3. A/B 账号隔离、切换账号、拉黑/禁言/失去位置或成员资格；
4. 更早消息、第一条未读、搜索结果和 @/回复锚点定位；
5. 图片、语音、视频、表情和位置消息的缓存、过期占位及清理；
6. 服务器重启、多设备已读、100 人并发和保留期限清理。

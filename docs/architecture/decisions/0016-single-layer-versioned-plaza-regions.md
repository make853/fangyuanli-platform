# ADR 0016：单层版本化广场区域与区域内命名硬约束

- 状态：已接受
- 日期：2026-08-03
- 补充并修正：ADR 0012、0013、0014、0015 中关于固定网格和格心附近命名的边界

## 背景

两公里方格和四广场联合命名已经可以稳定生成广场身份，但真实验收发现，被分配给西南方格的“逍遥苑广场”实体实际位于用户东南方向；“民权北站站前广场”也可能离用户约 3.9 公里。原因是候选发现允许从格心搜索三公里，却没有要求最终地标落在所属方格内部。

与此同时，正式运营后可能需要根据匿名聚合密度、道路河流、社区和商圈边界调整广场范围。业务不能永久绑定正方形，也不能同时存在一套网格群聊和一套不规则区域群聊，否则消息、未读和管理关系会产生双重归属。

## 决策

1. 用户可见、承载会话的广场只有一层权威区域。首版边界由 2000 米正方形生成；未来同一领域模型可以使用 Polygon 或 MultiPolygon，不再创建第二层业务广场。
2. 全图分区规则逻辑上预先确定，但数据库按真实用户首次需要懒创建区域记录、名称和会话。技术空间索引或内部瓦片只用于查询加速，不拥有名称、成员、消息或管理权限。
3. 同一生效地图版本中的基础广场必须形成无重叠、无空缺的平面分区，任意坐标恰好归属一个区域。共享边界采用确定性的左闭右开等统一规则，不能重复归属。
4. 地图供应商可以在区域之外搜索以发现足够候选，但最终自动名称必须同时满足：存在合法 GCJ-02 坐标、坐标被当前区域覆盖、语义和稳定性排序合格。格外地标不得借给当前区域；无合格候选时使用中性编号。
5. 自动名称持久化地图供应商、供应商 POI 标识和选中坐标，用于边界包含审计和策略重算。这些字段均不是广场身份；广场、会话和历史消息只依赖稳定 `plaza_id` / `conversation_id`。
6. 边界调整以完整地图版本原子发布。一个区域缩小时，释放面积必须在同一版本中分配给相邻区域；扩大时必须同时从受影响相邻区域扣除。发布前验证多边形合法性、全域覆盖、零重叠和用户迁移影响。
7. 单纯重塑边界时保留 `plaza_id`、会话和消息。真正拆分或合并时创建新的区域身份并记录谱系，旧消息不按新边界重写归属。广场没有群主或管理员，治理能力属于平台层。
8. 密度自适应使用脱敏聚合数据生成建议，并经过模拟和审核；不得因一天的人流或 GPS 漂移实时改变区域。150 米锚点继续负责用户侧稳定，不改变区域边界。
9. 大型体育场、景区和临时活动场地使用独立场所覆盖能力，不通过反复挤压居民基础广场来表达短期人流。

## 当前实施阶段

- 命名策略版本 6 为现有两公里方格增加严格点包含过滤；候选没有坐标或位于格外时不得进入四格联合分配。
- 旧策略的跨格自动名称在成功完成新一轮地图查询后，如果找不到格内替代候选，应退回稳定中性编号并按退避周期重试；地图请求失败时保留旧值，避免定位主流程受影响。
- 迁移保存最终命名 POI 的供应商、POI 标识和 GCJ-02 坐标。当前不提前引入任意多边形编辑器；在真实密度数据和运营工具出现前，区域仍使用两公里正方形实现。

## 验收

1. 格外高分地标不能击败格内低分但合格的地标；
2. 某格只有格外候选时不再保留旧跨格名称，而回退为自身中性编号；
3. 位于共享边界的点只属于一个方格；
4. 命名审计字段保存最终 POI 坐标，改名不改变广场和会话身份；
5. 高德失败仍不阻塞地理上下文，旧名称只在成功取得候选集后按新策略校正；
6. 产品规格、DBML、SQL 迁移和自动测试同步通过。

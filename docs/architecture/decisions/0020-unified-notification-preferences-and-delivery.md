# ADR 0020：统一通知偏好与投递边界

## 状态

已接受，2026-08-09。

## 决定

1. 私聊、广场、地点和活动统一使用 `conversation_notification_settings`，业务页面不得保存第二份通知开关；
2. 服务端计算最终有效模式：单会话 `normal` / `muted` 优先于全局群免打扰，私聊不继承全局群免打扰；
3. 应用内红灰未读、底栏未读、桌面图标角标和系统推送必须消费同一份服务端未读与有效通知模式；
4. 移动端修改设置后先使用服务端返回值更新本地快照，再通过实时事件校准其他登录设备；
5. APNs、未来 Android 推送和测试替身均实现独立投递端口，消息与会话领域不得直接依赖厂商 SDK；
6. APNs 设备令牌按账号和安装实例登记，每次系统回调都上传最新令牌，不把令牌当作永久设备身份；
7. 系统通知只携带不透明目标标识和导航信息，不携带精确位置或受隐私规则保护的资料。

## 当前纵切

- 已接入真实单会话通知设置接口；
- 广场信息页可即时开启通知或免打扰，红灰未读和底栏统计同步变化；
- 下一批增加安装实例、APNs 令牌登记、图标角标同步、服务端投递端口和通知点击导航。

## 风险控制

- 未取得 Apple 推送能力和密钥前，服务端适配器必须明确处于未配置状态，不伪装投递成功；
- 设置写入要求幂等键，账号切换沿用共享鉴权客户端的账号防线；
- APNs 属于尽力投递，客户端恢复后仍以服务端未读与增量同步为权威，不能以推送到达代替消息同步。

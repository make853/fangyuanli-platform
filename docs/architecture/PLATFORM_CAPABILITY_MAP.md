# 方圆里平台公共能力地图

> 目标：同一能力只拥有一套权威状态和实现，广场、地点、活动、好友与动态通过场景策略复用，避免平行状态机和连锁回归。

## 1. 分层原则

```text
页面与场景适配器
    ↓ 只表达场景差异
应用能力与领域策略
    ↓ 只通过稳定端口
数据库、缓存、实时、对象存储和系统能力
```

- 页面负责展示、输入和导航，不决定服务端权限；
- 场景模块拥有自身业务规则，不复制通用基础设施；
- 公共能力不得演变为包含所有业务字段的万能模型；
- 跨模块修改通过应用服务和可靠事件执行，不直接修改其他模块的数据；
- 性能问题以构建范围、状态订阅、I/O、缓存命中和异步竞态为证据，不以“文件数量多”或“代码行数多”代替测量。

## 2. 能力所有权

| 公共能力 | 权威所有者 | 场景提供的策略 | 禁止的重复实现 |
|---|---|---|---|
| 账号、设备、会话令牌 | `identity` | 登录入口、资料展示 | 业务 Repository 自建鉴权客户端或猜测当前账号 |
| 好友、拉黑、单向设置 | `relationships` | 来源文案、场景入口 | 聊天或动态页面自行推断关系和越权放行 |
| 坐标、区域、锚点、访问凭证 | `geo` | 广场/地点/活动的资格策略 | 客户端自行划分权威区域或长期保存短期位置令牌 |
| 会话、消息序号、已读、搜索 | `conversations` | 会话类型、访问上下文、发言策略 | 广场、地点、活动、私聊分别建立消息表和同步控制器 |
| 乐观发送、失败、幂等重试 | 统一 conversation outbox | 消息载荷和短期权限解析器 | 各页面自行排队、生成第二个幂等键或等待网络后才显示 |
| 输入框、键盘、表情、附件、语音 | Flutter `ChatComposer` | 可用动作、底部宿主高度 | 业务页面叠加第二套键盘高度、动画或延迟补丁 |
| 消息时间线、最新位置、未读锚点 | Flutter conversation presentation | 消息气泡和场景菜单 | 各聊天页面自行滚动到底部或维护另一套列表方向 |
| 本地缓存、同步游标、账号隔离 | Flutter 统一 SQLite 与同步引擎 | 数据保留和失效策略 | 每个功能自行打开数据库、用页面内存冒充持久缓存 |
| 导航、返回、入口来源 | Flutter navigation contract | 入口元数据、目标实体 | 全局变量猜来源、无条件跳首页或复制目标页面 |
| 媒体上传、处理、签名读取、清理 | `media` 与统一上传协调器 | 头像、聊天、动态、活动等用途 | 各模块直传长期密钥、分别建立媒体重试队列 |
| 未读汇总、免打扰、推送 | `notifications` + conversation cursor | 导航分类、场景通知策略 | 页面根据临时红点自行计算权威未读 |
| 举报、证据、审核、禁言、封禁 | `governance` | 内容类型和处置入口 | 各模块建立互不兼容的举报状态和审计记录 |
| 地点认领、认证、热度、地点管理 | `places` | 地点类型和角色权限 | 会话组件承担商家认证或地点边界规则 |
| 活动、报名、审批、结束状态 | `activities` | 活动成员和发言策略 | 通用聊天状态机承担活动生命周期 |
| 动态、点赞、评论、可见性 | `posts` | 分发范围和互动规则 | 资料页复制动态数据或评论页面自建用户投影 |

## 3. 平台能力与场景差异的判断

满足以下多数条件时，应优先扩展公共能力：

1. 会出现在三个及以上模块；
2. 数据含义和生命周期相同；
3. 修改时用户期望所有场景一起变化；
4. 多端同步、离线、幂等、权限或安全要求相同；
5. 分别实现会产生多套权威状态。

仅仅“长得相似”不足以抽象。地点认证和活动报名都可能使用列表及按钮，但领域状态、权限和数据保留不同，应留在各自模块，通过公共导航、媒体、通知和会话端口组合。

## 4. 公共能力变更检查表

平台级修改开始前必须回答：

- 用户可观察行为是什么；
- 当前权威状态由谁拥有；
- 哪些模块会受影响；
- API、实时事件和数据库是否变化；
- 旧客户端、旧缓存和历史数据如何兼容；
- 失败、断网、重复操作和后台恢复如何表现；
- 自动测试、A/B测试和真机验收覆盖哪些场景；
- 如何回滚到上一个稳定 Git 检查点。

## 5. 当前复用基线

已形成并禁止平行实现：

- 账号隔离的鉴权网络客户端；
- 本地优先资料快照与版本化用户投影；
- 统一会话缓存、同步、序号、已读和实时合并；
- 持久化 outbox、乐观发送、失败提示与幂等重试；
- 统一聊天输入区域和底部占位；
- 消息时间线最新位置与可见性驱动的已读；
- 统一媒体上传、处理、签名读取和任务恢复。

地点、活动和动态接入时，先为场景补充访问策略、领域对象和页面适配器；发现公共底座不足时扩展底座并回归已有私聊与广场，禁止先在新页面复制一套临时代码。

## 6. 完成定义

一项公共能力只有同时满足以下条件才可冻结：

1. 行为合同和所有者明确；
2. 没有绕过公共边界的场景实现；
3. 静态分析与自动测试通过；
4. 相关 A/B、离线、重连和权限场景通过；
5. 对体验敏感的能力完成真实设备验收；
6. 文档、交接状态、Git提交和CI一致；
7. 没有把临时截图、密钥、设备ID和调试日志提交进仓库。
